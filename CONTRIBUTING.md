# Contributing

Thanks for contributing! Here are some guidelines to help you contribute.

## Creating an issue

- Please check if another issue exists for this problem.
- When reporting a bug, include your calculator model and software version (or the emulator and version)
- For suggestions or feature requests, explain why it would be useful.
- It's recommended to use an issue template

## Good practices for code

- Try to add some comments.
- Use snake_case for variables/functions and PascalCase for classes.
- Test every change on a physical NumWorks device.

## Creating pull request

- Use clear commit message.
- Add reasons for your commit and explanations in the PR description.
- Write commit messages and PR descriptions in English (it doesn't need to be perfect English) and avoid complex English.
- Keep the _Allow edits from maintainers_ checkbox selected, so edits can be bond if needed.

## Notice on AI usage

### For code writing
You can use AI to explain something that you can't find online or autocompletion tools in IDEs, but you need to always understand every line of code that you are writing. Fully vibe coded pull requests are ptohibited.

### For commit messages/issues
You can use AI to check if your English is correct (even if you dont need to have a perfect English) or to check if there's no errors, but you need to read and understand everything.
If you can't explain you changes, you should maybe not push these changes
